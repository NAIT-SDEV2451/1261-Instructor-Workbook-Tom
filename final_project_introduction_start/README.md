# Final Project Introduction

In the final project, you'll be in a group of 3-4 team members and building a full stack application using the concepts you've learned in this course. This is going to be a big project and will require you to work together as a team to complete it. You will be expected to use GitHub for version control and collaboration, and you will be graded on your ability to work together as a team, as well as the quality of your code.




## This project is to prepare you for capstone so that your next semester goes smoothly.
- This is not only going to test your software knowledge but your collaboration, communication, and time management skills.
- You'll get to make teams of 4 together that you will pick and folks who don't show up will get put in a team together to not impede on other team members.
- **You can't do this in pairs, you can't do it solo.**
- **Everyone will need to contribute.**
- **Everyone will need to review each others code.**
- You will have 4-5 weeks to complete this.
- You will be not only graded on the progress and "completeness" on the project (which is half) but how you collaborate as well (which is the other half)
- If you don't contribute you will get a significantly worse mark than others.

- What I will need:
  - All of your github user names.
  - The repo that will be used for the project (only one repo per team.)

## This is going to be difficult

### Team management aspects
- You will be managing a software project on your own with guidance from me and what you've learned in this course so far.
  - We'll create a github project and ensure all of you folks have access to it.
- You will be expected to fix your own merge conflicts but if you can't there are days where you can ask the instructor for help.
  - You'll need to also do some learning on your own to figure out how to do this I should be the last resort.
- You will be REQUIRED to show up (in person) for four standup meetings which I will attend during class which will include.
  - things you've done over the past week.
  - things you're currently working on.
  - things you're stuck on (where I can help as well.)
  - Note: excuses afterwards will not be accepted unless there's extreme circumstances, you will need to give your progress in a standup before you show up.
    - You can't do it 4 weeks in advance as you need to show your progress of the last week.
  - Note: you can keep track of this in a document or a github issue.
  - I need to be present for your stand up.


## Keep track of the following in a document on your own
- things you've learned
- Conflicts and how you've resolved them
- How yourself and other folks are performing in contributions on the team.
  - If some one isn't your group isn't contributing you need to let me know so that I can help you folks out.
    - Honest Effort is expected from everyone, as you're going to be marked individually on this project.
    - Note: if you don't let me know I can't help you.
- How you're using AI to help develop your project.
- All links of:
  - Your own pull requests.
  - Your own reviews on pull requests.
- This will help you for lab 4 which is a retrospective on the lab.
